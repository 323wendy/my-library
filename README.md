# 나만의 기록 🗂️

읽은 책(📚), 본 영상(🎬), 정주행한 웹툰·웹소설(🖍️)을 한곳에 모으는 모바일 웹앱입니다.
서버도, 로그인도, 빌드도 필요 없습니다. `index.html`을 열면 바로 동작하고,
GitHub Pages에 올리면 폰 홈 화면에 앱처럼 설치할 수 있습니다.

- 실서비스: <https://323wendy.github.io/my-library/>
- 기록은 세 개의 JSON 파일에 나뉘어 저장됩니다: `books.json` · `videos.json` · `webtoons.json`

## 화면

- **세 가지 탭** — 📚 독서 / 🎬 영상 / 🖍️ 웹툰·웹소설. 탭마다 자기 기록만 보여 주고, 탭마다 포인트 색이 살짝 다릅니다(크림 · 라벤더 · 피치).
- **목록 보기** — 3열 표지 그리드, 분류 칩(전체 / ❤️ / 분야…), 상태 칩(전체 / 완료 / 중단 / 보는 중), 제목·저자·한 줄 평·문구 실시간 검색.
- **정렬** — '보는 중'(책은 '읽는 중')이 항상 맨 앞, 나머지는 끝난 날짜 최신순. 날짜가 없으면 맨 뒤.
- **등록/수정** — 제목을 넣으면 표지·인물·분야를 자동으로 찾아 줍니다(세 탭 모두).
  - 📚 독서: `🔍 표지·저자 찾기` → 저자·표지·분야 (Google Books · Open Library)
  - 🎬 영상: `🔍 표지·감독 찾기` → 감독·포스터·분야(영화/드라마/애니/예능/다큐) (위키데이터 · 한국어·영어 위키백과)
  - 🖍️ 웹툰·웹소설: `🔍 표지·작가 찾기` → 작가·표지·종류(웹툰/웹소설)·플랫폼 (위키데이터 · 한국어 위키백과 · AniList · Google Books)

  영상·웹툰 탭은 제목을 두 글자 이상 치면 잠시 뒤 저절로 찾아 보고, 후보를 한 번 누르면 입력칸이 채워집니다. 키도 서버도 필요 없이 브라우저에서 공개 API를 바로 부릅니다(모두 CORS 허용). 시작한 날짜·끝난 날짜, 상태, 분류를 함께 기록합니다.
- **상세** — 큰 표지, 제목·저자/감독, 분류·플랫폼·본 기간·하트 칩, 한 줄 평, 💬 문구(명대사) 추가·수정·삭제, 링크 열기, 수정/삭제.
- **통계** — 탭마다 따로: 총 완료 / 올해 완료 / ❤️ 하트, 연도별·월별 막대, 분류 분포(%). 중단·보는 중은 통계에 넣지 않고 따로 작게 보여줍니다.
- **기기 간 동기화** — GitHub 토큰을 한 번 넣으면 세 파일이 각각 동기화됩니다. 한 탭을 저장해도 다른 탭의 파일은 건드리지 않습니다.
- **데이터 복사 & 이동** — 지금 탭의 기록을 JSON으로 복사하고, 다른 브라우저로 옮기거나 백업.

```

├─ core.js                 데이터 로직 (세 기록 종류 정의, 파싱/병합/통계) — DOM 없이 동작
├─ sync.js                 기기 간 동기화 (GitHub Contents API, 파일별)

├─ videos.json             영상 기록
├─ webtoons.json           웹툰·웹소설 기록
├─ covers/                 예전 샘플 책 표지 이미지
```

## 배포하기 (GitHub Pages)

1. GitHub에서 새 저장소를 만듭니다(공개 저장소면 무료 Pages 사용 가능).
2. 이 폴더의 파일을 **폴더째** 올립니다.

   ```bash
   git init
   git add .
   git commit -m "나만의 기록"
   git branch -M main
   git remote add origin https://github.com/<아이디>/<저장소>.git
   git push -u origin main
   ```

3. 저장소 **Settings → Pages** 에서 Source를 `Deploy from a branch`, Branch를 `main` / `(root)` 로 저장합니다.
4. 1~2분 뒤 `https://<아이디>.github.io/<저장소>/` 주소로 열립니다.

> 저장소를 비공개로 두면 무료 계정에서는 Pages가 열리지 않습니다.

## 폰에 앱처럼 설치하기

- **안드로이드 크롬 / 삼성 인터넷**: 주소창 오른쪽 메뉴 → `홈 화면에 추가` (또는 `앱 설치`)
- **아이폰 사파리**: 공유 버튼 → `홈 화면에 추가`

## 기록 추가하는 두 가지 방법

**1) 앱에서 직접** — 오른쪽 위 `+ 등록` → 제목을 넣고(독서 탭은 `🔍 표지·저자 찾기`) 날짜·상태·분류를 고른 뒤 저장합니다.
이 내용은 그 폰의 브라우저(`localStorage`)에 저장되고, 동기화를 연결했다면 GitHub 파일에도 반영됩니다.

**2) JSON 파일에 올리기** — `books.json` / `videos.json` / `webtoons.json`의 배열에 항목을 추가하고 GitHub에 올리면,
앱을 다시 열 때 자동으로 내려받아 보여줍니다.

```json
// books.json → books[]
{ "id": "chotdol", "title": "쇳돌", "author": "이라영", "category": "인문",
  "startDate": "2026-09-10", "endDate": "2026-09-17", "status": "완독",
  "cover": "covers/chotdol.jpg", "memo": "사라지는 노동의 목소리.", "heart": true, "quotes": [] }
```

```json
// videos.json → items[]
{ "id": "v-1", "title": "기생충", "creator": "봉준호", "kind": "영화",
  "startDate": "", "endDate": "2026-11-15", "status": "봤음",
  "cover": "https://…/poster.jpg", "note": "계단의 의미.", "heart": true, "quotes": [], "link": "" }
```

```json
// webtoons.json → items[]
{ "id": "w-1", "title": "그저 여명일 뿐", "creator": "강기 (원작 우지혜)", "kind": "웹툰",
  "platform": "리디", "startDate": "2026-01-13", "endDate": "2026-01-15", "status": "완독",
  "cover": "https://…/cover.jpg", "note": "", "heart": true, "quotes": [], "link": "" }
```

- `id`는 항목마다 겹치지 않게. 한 번 정하면 바꾸지 않는 편이 좋습니다.
- 날짜는 `YYYY-MM-DD`, 모르면 `""`. 영화처럼 하루면 `endDate`만 채워도 됩니다. 예전처럼 `finishedAt`·`date` 하나만 있어도 **끝난 날짜**로 읽습니다.
- `status`는 표의 상태 말. 없으면 완료로 봅니다.
- `cover`는 상대 경로나 `https://…`. 비우면 파스텔 기본 표지가 그려집니다.
- 문구는 `quotes` 배열(`[{ "id": "q1", "text": "…", "page": "42" }]`). `page`는 독서 탭에서만 씁니다.
- 영상·웹툰의 `note`는 한 줄 감상입니다. 배열로 여러 개를 넣으면 문구 목록으로 읽습니다.

## 기기 간 동기화 (선택)

`☁️ 동기화` 버튼 → **GitHub 토큰**을 한 번 넣으면, 이 기기의 기록이 저장소의
`books.json` · `videos.json` · `webtoons.json`에 각각 저장되고 다른 기기와 같은 기록을 쓰게 됩니다.
토큰을 넣지 않아도 앱은 그대로 동작합니다(JSON을 읽어 오고, 고친 내용은 그 브라우저에만 저장).

- 토큰은 그 브라우저의 `localStorage`(`reading-app:sync`)에만 저장되고, 기록·저장소·JSON에는 절대 담기지 않습니다. `연결 해제`로 언제든 지울 수 있습니다.
- **파일별로 따로** 동기화합니다. 독서 탭에서 저장해도 `videos.json`·`webtoons.json`은 그대로입니다.
- **자동 저장**: 추가·수정·삭제·하트·문구 변경이 0.9초 모아져 해당 파일에 반영됩니다.
- **충돌**: 다른 기기가 먼저 저장해 `409 Conflict`가 나면 최신 파일을 다시 받아 `updatedAt`이 더 최근인 쪽으로 합친 뒤 한 번 재시도합니다.
- **다른 기기 변경**: 45초마다(그리고 앱으로 돌아올 때) 세 파일을 확인합니다. 다른 기기에서 지운 기록은 이 기기에서도 지워집니다.
- **공개 저장소**라면 올린 기록(제목·한 줄 평·문구)은 누구나 볼 수 있습니다.

## 데이터는 어떻게 저장되나요

- `books.json` · `videos.json` · `webtoons.json` = **모두에게 보이는 기본 목록**.
- 브라우저 `localStorage` = **내가 고친 내용·내가 등록한 기록·내가 지운 기록**만, 탭별로 따로.
- 앱을 열 때 두 가지를 **`id` 기준으로 합칩니다.** 그래서 앱에서 고치거나 지운 기록은 JSON이 바뀌어도 내 선택이 유지되고, JSON에 새로 올라온 기록은 폰에도 나타납니다.
- 웹툰·웹소설은 따로 된 칸에서 봅니다. 예전에 독서 목록에 있던 웹툰·웹소설은 `webtoons.json`으로 옮겼습니다.
- 브라우저마다 저장 위치가 달라서 **크롬에서 넣은 기록은 삼성 인터넷에 자동으로 넘어가지 않습니다.**
  통계 탭의 `데이터 복사하기` → 다른 브라우저에서 `데이터 불러오기`로 옮기세요.

## 개발 메모

- 외부 라이브러리 없음. 데이터 `fetch`는 캐시를 피하려고 `?t=시간`을 붙입니다.
- `core.js`는 화면과 분리되어 있어 브라우저 없이도 테스트할 수 있습니다(`module.exports` 지원). 세 기록 종류의 정의(`COLLECTIONS`)도 여기에 있습니다.
- 서비스 워커는 앱 껍데기만 캐시하고 기록 JSON 세 개는 항상 네트워크를 먼저 확인합니다.
  코드를 고친 뒤 폰에서 옛 화면이 보이면 `sw.js`의 `CACHE` 이름(`shelf-v6`)을 올리면 됩니다.
- 동기화는 `core.js`의 `mergeForSync`(순수 함수)와 `sync.js`(통신·상태, 파일별)로 나뉩니다. 병합 규칙은 `mergeForSync` 한 곳에만 있습니다.
- 표지·저자 검색은 `books.google.com/books/feeds/volumes`(키 없이 CORS 허용)와 `openlibrary.org`를 함께 써서 결과를 합칩니다.
  Google Books의 `www.googleapis.com/books/v1`은 키 없는 요청이 하루 할당량 0으로 막혀 있어 마지막 순서로만 시도합니다.
- 다크 모드는 없습니다(`color-scheme: light` 고정). 기기·브라우저의 강제 다크 변환에도 파스텔 색이 그대로 보이도록 했습니다.
